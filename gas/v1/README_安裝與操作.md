# PSS AI-PMO V20.5 R5.2｜工作回報與任務流程修正版

適用基準：目前線上 `V20.5 R5.1 Training Center Rebuild` 主程式。

這是「增量補丁」：安裝器會先從正式 Apps Script 拉回目前 HEAD 原始碼、建立本機 ZIP 備份，再加入 R5.2 檔案並更新原 Deployment。它不會用舊版 `Code.gs` 或 `Index.html` 覆蓋正式系統，也不會刪除資料表或既有欄位。

## 1. 本版修正

1. 專案搜尋統一改讀正式「專案清單」索引。
2. 輸入 1 個字以上立即篩選；空白時連點兩下或按方向鍵向下，顯示前 50 筆專案。
3. 修復正式 R5.1 `projectCellHtmlV18()` 被截斷的 URL 正規表示式；此語法錯誤會讓整段動態專案模組無法載入。
4. 修正任務按「回報」時仍寫入已刪除 `batchStatus_*` 欄位而產生的：

   `Cannot set properties of null (setting 'value')`

5. 任務點選後改開啟「任務工作區」，可：

   - 編輯任務內容、類型、期限、狀態及備註。
   - 新增附件／照片。
   - 新增工作回報。
   - 回報並完成任務。
   - 新增同專案關聯任務／正式派工。
   - 檢視並開啟相關回報與同專案任務。

6. 回報紀錄增加「編輯回報」與「開啟原任務」：可修改日期、時間、跨日、地點、專案、標題、內容、附件，並可同步完成原任務。
7. 首頁新增「我的工作收件匣」：

   - 今日新派工。
   - 逾期未完成。
   - 7 日內到期。
   - 之前工作留下的正式後續任務。

8. 關聯資訊抽屜增加「編輯／回報任務、標示完成、新增專案派工」快捷操作。
9. 新增 `SYS_任務回報歷程`，記錄任務編輯、工作回報、完成及關聯任務，不改寫舊回報歷史。

## 2. 安裝前準備

- Windows 電腦已安裝 Node.js 20 以上版本。
- Apps Script 使用者設定已啟用 Apps Script API。
- 執行 `npx @google/clasp login` 完成 Google 帳號授權。
- 從主 PMO 的 Apps Script「專案設定」取得 Script ID。
- 從「部署 → 管理部署作業」取得目前 `/exec` 使用的 Deployment ID。

Script ID 不是 `/exec` 網址中的 `AKfy...` 字串；兩者不可混用。

## 3. 安裝

1. 解壓縮安裝包。
2. 將 `Installer/install-config.template.json` 複製為 `Installer/install-config.json`。
3. 填入：

   - `scriptId`：主 PMO Apps Script 專案 ID。
   - `deploymentId`：目前主 PMO Web App Deployment ID。

4. 雙擊 `Installer/Validate_R52.cmd`，確認顯示 `R5.2 validation PASSED`。
5. 雙擊 `Installer/Install_R52.cmd`。
6. 安裝器會依序：

   - 下載正式 HEAD。
   - 在 `backups` 建立更新前 ZIP。
   - 新增 `PSS_Workflow_R52.gs`。
   - 將 R5.2 前端插入現有 `Index.html` 最後面。
   - `clasp push --force`。
   - 使用原 Deployment ID 更新 `/exec`。

7. 打開 Apps Script 編輯器，手動執行一次：

```javascript
setupPssWorkFlowR52()
```

8. 再執行：

```javascript
runPssWorkFlowSelfTestR52()
```

應看到專案清單、任務派工、每日工作日誌、任務回報歷程、附件模組與專案索引均為正常。

## 4. 操作流程

### 4.1 使用者每天開始工作

1. 登入首頁。
2. 查看「我的工作收件匣」。
3. 優先處理逾期，再處理 7 日內到期及今日新派工。
4. 點任務的「編輯／回報」。
5. 完成一段工作就新增回報；真正完成整項任務時再按「回報並完成任務」。

### 4.2 專案搜尋

- 直接輸入 1 個字、場地代號、客戶、專案名稱、系統、主管或地址即可篩選。
- 搜尋框空白時連點兩下，顯示專案清單前 50 筆。
- 若剛新增／修改專案仍找不到，重新登入或按頁面重新整理，使正式索引重新載入。

### 4.3 編輯既有回報

1. 進入「每日回報」。
2. 在回報紀錄按「編輯回報」。
3. 修改內容或補上附件。
4. 若該工作已真正完成，可勾選「同時將原任務標示完成」。
5. 儲存後會刷新首頁、任務及回報資料。

### 4.4 新增關聯事項與派工

1. 開啟任務工作區。
2. 在「新增關聯任務／正式派工」輸入內容、負責人、期限、優先級及備註。
3. 建立後會成為正式任務，出現在負責人的工作收件匣。
4. 後端會記錄來源任務 ID，保留工作脈絡。

一般人員只能新增指派給自己的關聯任務；主管可指派給其他人。

## 5. 驗收清單

- [ ] 空白專案搜尋框連點兩下會顯示專案。
- [ ] 輸入 1 個字可篩選資料庫專案。
- [ ] 任務按「回報」不再出現 null value 錯誤。
- [ ] 任務工作區可儲存編輯。
- [ ] 任務可新增附件。
- [ ] 任務可新增回報但不會誤完成。
- [ ] 「回報並完成」才會完成任務。
- [ ] 回報紀錄可重新編輯與補附件。
- [ ] 關聯任務會出現在負責人的工作收件匣。
- [ ] `SYS_任務回報歷程` 有留下操作紀錄。

## 6. 回復

若正式驗收失敗：

1. 不要執行任何資料刪除。
2. 使用 `backups/PMO_HEAD_before_R52_日期時間.zip` 還原更新前原始碼。
3. 重新 `clasp push --force` 並更新原 Deployment ID。

R5.2 新增的 `SYS_任務回報歷程` 可以保留，不影響舊版；不要直接刪除正式任務與每日回報資料。
