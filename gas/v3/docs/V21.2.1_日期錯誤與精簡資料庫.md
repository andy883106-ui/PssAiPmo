# V21.2.1｜日期錯誤與 V2.0 精簡資料庫

## 週四會議錯誤原因

`v21BuildThursdaySnapshot_()` 先把 Date 物件位移成 `yyyy-MM-dd` 文字，再次位移時舊函式仍直接執行 `date.getTime()`，因此出現：

`date.getTime is not a function`

V21.2.1 的日期位移函式會先判斷輸入；若為文字日期，先安全轉回 Date 再運算。

## 建議先恢復週四會議

1. 更新 V21.2.1 全部 `src` 檔案。
2. 執行 `runV21SelfTests()`，確認 20 項全部通過。
3. 編輯原 Web App 部署並選擇「新版本」。
4. 重新開啟 `/exec`，點週四會議及「重新偵測資料庫」。

## 建立 V2.0 精簡資料庫

先執行 `previewCleanV20DatabaseV21()`；此步驟只分析，不建立、不刪除、不切換資料庫。確認執行記錄中的來源與保留筆數後，再執行 `runCreateCleanV20DatabaseV21()`。

建立規則：

- 專案：保留尚未完成、結案、取消或作廢者；若仍有進行中／待追蹤工作，即使專案狀態已結案仍保留。
- 工作：只保留進行中與待追蹤。
- 回報：保留最近 180 日且屬於保留專案。
- 歷程：保留上述專案的完整歷程。
- 圖面：每個保留專案保留目前有效圖面狀態。
- 教材、設備媒體、會議紀錄：保留仍有效資料。
- 報價：保留未取消、未作廢報價及其明細。
- 快照與操作紀錄：不搬移，在新資料庫重新產生。

建立完成後，函式會回傳新試算表網址並設定為程式目標。原資料庫維持原狀，可隨時用 `configureV21TargetDatabase('舊資料庫ID')` 切回。

## 建議執行順序

1. 先修正與重新部署程式。
2. 匯入 2026/08/13 會議紀錄。
3. 執行精簡資料庫預覽。
4. 建立 V2.0 精簡資料庫。
5. 回到 Web App 按「重新偵測資料庫」，建立新資料庫第一份週四會議快照。
