# V21.1.1 空白頁與部署診斷

## 已確認現象

提供的網址結尾為 `/dev`，屬於開發測試網址。未登入或沒有 Apps Script 專案編輯權限時會導向 Google 登入；它不是一般使用者的正式入口。同一部署代號的 `/exec` 目前也要求登入，表示部署存取權至少不是匿名公開。

## 程式修正

1. `doGet(e)` 包住模板建立與解析錯誤。
2. 缺少 `Index.html`、`Styles.html` 或 `App.html` 時，顯示錯誤內容與正確檔名，不再只有白畫面。
3. 網址加上 `?diagnostic=1` 時，直接檢查：
   - `doGet` 是否執行；
   - Apps Script 授權狀態；
   - V21 目標資料庫是否可開啟；
   - 三個 HTML 檔案是否存在。
4. 前端資料 API 失敗時，錯誤會顯示在專案搜尋框下方。

## 正確重新部署

1. 將 V21.1.1 內 13 個 `.gs`、3 個 `.html` 與 `appsscript.json` 更新到同一個 Apps Script 專案；檔名大小寫必須完全相同。
2. 儲存後執行 `runV21SelfTests()`，應有 11 項通過。
3. 執行 `setupPssAiPmoV21()` 與 `healthCheckV21()`；首次執行需完成 Google 授權。
4. 點「部署 → 管理部署作業 → 編輯」並選擇「新版本」。
5. 類型選「網頁應用程式」、執行身分選「我」。存取權可依公司政策選「網域內使用者」或「任何已登入 Google 帳戶的使用者」。
6. 完成後複製結尾為 `/exec` 的網址，不使用 `/dev` 作正式入口。
7. 先開啟 `/exec?diagnostic=1`。若顯示資料庫可開啟且三個 HTML 均存在，再開啟一般 `/exec`。

## 判讀

- 顯示 `Index.html：找不到`：HTML 檔名或貼檔不完整。
- 顯示 `REQUIRED`／需要授權：回到編輯器執行 `healthCheckV21()` 並完成授權。
- 顯示資料庫無法開啟：部署者沒有試算表權限，或目標資料庫 ID 設定錯誤。
- 診斷頁全部正常但主頁資料載入失敗：搜尋框下方會顯示後端實際錯誤，可依該錯誤繼續修正。
