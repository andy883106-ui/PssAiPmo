# PSS AI-PMO V22.5.0 安裝、部署與回復流程

## A. 上線前

1. 備份目前 Apps Script 專案。
2. 備份目前 PSS AI-PMO 目標資料庫試算表。
3. 確認專案仍使用 `V21_專案主檔`、`V21_工作事項` 等 canonical sheets。
4. 確認專案資料夾 URL 與 Drive 權限正常。
5. 不要先刪除 V22.4.0 的 deployment。

## B. 使用 Apps Script 編輯器上線

1. 開啟原 Apps Script 專案。
2. 將本包 `src/` 內的程式檔同步到專案。
3. 新增：
   - `22_CalendarWorkService.gs`
4. 覆蓋：
   - `00_Config.gs`
   - `04_WorkReportService.gs`
   - `06_Web.gs`
   - `12_ThursdayMeetingService.gs`
   - `Index.html`
   - `App.html`
   - `Styles.html`
5. 其他原有 `.gs/.html/appsscript.json` 保持不變。
6. 儲存全部檔案。
7. 執行一次 `healthCheckV21()`。
8. 若系統提示授權，使用實際擁有資料庫與 Drive 權限的帳號完成授權。
9. 執行一次 `refreshDailyProjectionV21()`，確認資料庫可讀。
10. 開啟測試部署，驗證日曆、新增、編輯、完成（不追蹤）、刪除、附件。

Google Apps Script 的部署設定包含執行身分與存取權；正式 Web App 請依原本 V22.4.0 的安全設定維持，不要任意放寬存取權。

## C. 正式 Web App 部署

1. Apps Script：Deploy → Manage deployments。
2. 編輯現有 Web App deployment 或建立新 deployment。
3. 類型選 Web app。
4. Execute as：依原系統設定；若資料庫與 Drive 是由管理帳號持有，通常維持原管理帳號執行。
5. Who has access：依公司帳號政策設定。
6. Deploy。
7. 取得 `/exec` 正式網址。
8. 用無痕視窗／實際使用者帳號測試。
9. 不要把 `/dev` 當成正式網址。

## D. 建議的上線驗收

### 1. 日曆
- [ ] 開啟「工作日曆」。
- [ ] 切換上月／下月。
- [ ] 今天有工作時顯示。
- [ ] 同一天 2 筆以上時顯示「＋N 項」。
- [ ] 點「＋N 項」可展開。
- [ ] 點工作可編輯。

### 2. 工作 CRUD
- [ ] 新增工作。
- [ ] 修改工作標題、負責人、期限、狀態。
- [ ] 刪除工作。
- [ ] 刪除後首頁不再出現。
- [ ] 工作關聯同步移除。
- [ ] 附件索引同步移除。
- [ ] Drive 實體附件仍保留。

### 3. 完成
- [ ] 「完成（不追蹤）」可直接完成。
- [ ] 完成後不再顯示在「目前工作」。
- [ ] 完成後不再顯示在「工作日曆」。
- [ ] 專案完整流程仍可看到完成紀錄。

### 4. 週四會議
- [ ] 本週已完成工作進入「本週完成」。
- [ ] 已完成工作不回到待辦。
- [ ] 週四會議刷新後仍正確。

### 5. 附件
- [ ] 同一工作可上傳多檔。
- [ ] 附件名稱與連結可看到。
- [ ] 編輯工作後既有附件不消失。

## E. 回復

若新版本發生問題：

1. 先不要刪除 V22.5.0 deployment。
2. 將 Web App deployment 切回上一個可用版本。
3. 若程式碼需要回復，恢復 V22.4.0 的 source。
4. 資料庫不需要因本次版本而重建；V22.5.0 使用既有 canonical sheets。
5. 如果曾執行「刪除工作」，該工作資料列已被永久移除；因此上線前資料庫備份非常重要。
6. Drive 實體附件本版本不會因刪除工作而被刪除，可從原專案資料夾找回。

## F. 風險注意

本版本的「刪除工作」是資料庫硬刪除，不是狀態封存。若需要更嚴謹的企業級復原，下一版建議改成「軟刪除」欄位：
`刪除狀態、刪除人員、刪除時間、刪除原因`
並提供管理者「回復工作」。
